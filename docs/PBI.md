
### **Product Backlog Items (PBIs) by Module**


| Module | PBI No. | Feature Name | Detailed Description |
| --- | --- | --- | --- |
| **Module 1: User Authentication & Session Management** | PBI-1 | User Registration | Users can create a personal account by verifying their identity via an email confirmation code and setting a strong, secure password. |
|  | PBI-2 | User Login | Users can log in with their email and password. The system supports a "Remember Me" feature for extended session validity and implements a login attempt limit to temporarily lock accounts after a threshold of failed attempts. |
|  | PBI-3 | User Logout | Users can actively log out, which must invalidate the current server-side session (e.g., JWT/Session) and clear all credentials stored on the client side. |
|  | PBI-4 | Session Idle Timeout | The system monitors user activity and automatically expires sessions after a predefined period of inactivity. A warning modal will appear 1-5 minutes before expiration, prompting the user to extend the session or be logged out. |
|  | PBI-5 | Password Reset | Users can initiate a password reset from the login page. After verifying their identity via an email confirmation code, they will be allowed to set a new password, which takes effect immediately. |
| **Module 2: Customer Profile & Account Settings** | PBI-1 | View Personal Profile | After logging in, users can access their personal center to view their complete profile information (e.g., username, registered email, phone number, account status). |
|  | PBI-2 | Update Contact Information | Users can modify their email address and phone number. Changing an email address requires verification via a code sent to the new email to ensure its authenticity. |
|  | PBI-3 | Change Account Password | While logged in, users can change their password by first verifying their original password, enhancing account security. |
|  | PBI-4 | UI Theme Customization | Users can customize the visual theme of the interface, with a one-click toggle between Light Mode and Dark Mode. This preference should be synchronized with their account. |
|  | PBI-5 | Account Deletion | Users can request to permanently delete their account. The system must inform them of the consequences (e.g., loss of booking history) and, upon confirmation, either hard-delete or logically disable all associated data. |
| **Module 3: Specialist Profile & Category Management** | PBI-1 | Manage Specialist Categories | Administrators can create, edit, and delete professional specialty categories. The system must validate for non-empty, length, special characters, and uniqueness. Deletion is prohibited if a category is in use by any specialist. |
|  | PBI-2 | Add New Specialist | Administrators can add a new specialist by inputting their name, selecting a category from a dropdown, setting their tier, and defining their consultation fee. All required fields and positive fee values must be validated. |
|  | PBI-3 | Update Specialist Information | Administrators can edit a specialist's profile. The form will be pre-populated with existing data. Upon saving, validation is performed, and the record is updated, ensuring real-time synchronization across list and detail views. |
|  | PBI-4 | Modify Consultation Fee | Administrators can adjust a specialist's fee. The system validates for a positive number and prompts for confirmation on unusually large deviations. Fee changes only affect new bookings; historical orders remain locked. A modification log should be kept for auditing. |
|  | PBI-5 | Activate/Deactivate Account | Administrators can control a specialist's status. Deactivated specialists will not appear in booking lists. If there are pending bookings, the system must alert the admin and notify affected customers. |
| **Module 4: Availability Calendar Management** | PBI-1 | Create Single Time Slot | Specialists can create an available time slot on their calendar by selecting a date and start/end times. The backend must perform real-time overlap validation to prevent scheduling conflicts. |
|  | PBI-2 | Weekly Schedule View | Specialists can view their schedule in a weekly format, with different colors indicating "Available" and "Booked" statuses. The UI must disable drag-and-drop operations that would create overlaps. |
|  | PBI-3 | Delete Time Slot | Specialists can delete time slots that have not yet been booked. If a slot is already associated with a customer's booking, the delete action must be blocked with an appropriate error message. |
|  | PBI-4 | Modify Time Slot | Specialists can modify the start/end times of an unbooked time slot. The submission will trigger the overlap validation again to ensure logical consistency. |
|  | PBI-5 | Recurring Schedule Setup | Specialists can set up a recurring weekly availability (e.g., every Monday, 10:00-12:00). The system will auto-generate slots for future weeks, automatically skipping conflicting dates or public holidays. |
| **Module 5: Specialist Search & Details View** | PBI-1 | Filter by Category | Customers can filter the specialist list using a category dropdown menu to quickly find experts in a specific field. |
|  | PBI-2 | Keyword Search | Customers can perform an exact or partial match search by a specialist's name, with the list filtering in real-time to display matching results. |
|  | PBI-3 | Sort Functionality | Customers can reorder the search results based on specialist tier (high to low) or consultation fee (low to high / high to low). |
|  | PBI-4 | Filter by Availability | Customers can select a specific date to filter for specialists who have available time slots on that day, improving booking efficiency. |
|  | PBI-5 | Preserve State on Return | When a customer navigates back from a specialist's detail page, the system must retain their previous filter criteria, search keywords, and sort order. |
| **Module 6: Booking Request Creation & Validation** | PBI-1 | Time Slot Selection | After selecting a specialist, the customer can view their availability calendar and click on a specific time slot to book. |
|  | PBI-2 | Real-time Status Sync | The system must display the real-time status of time slots. Occupied slots should be grayed out and unclickable to prevent double-booking. |
|  | PBI-3 | Booking Form Submission | The customer fills in the consultation topic and any notes. The system validates the input for non-empty and length constraints to ensure data integrity. |
|  | PBI-4 | Dynamic Price Calculation | The system dynamically calculates the total fee based on the selected specialist's current rate and the duration of the booking, clearly displaying it to the customer before submission. |
|  | PBI-5 | Concurrency Conflict Validation | Upon submitting the booking request, the backend performs a final, atomic check to prevent the time slot from being booked by another user in the interval between selection and submission. |
| **Module 7: Booking Approval & Status Update** | PBI-1 | Pending Requests List | Specialists can view a list of all booking requests assigned to them with a "Pending" status, which should include the customer's name and request time. |
|  | PBI-2 | Booking Request Details | Specialists can click on a request to view the detailed consultation topic, notes, and the specific time requested by the customer to evaluate the booking. |
|  | PBI-3 | Approval/Rejection Action | Specialists can perform "Approve" or "Reject" actions on pending requests, which will trigger a status change in the system. |
|  | PBI-4 | Rejection Reason | When a specialist rejects a booking, the system must require them to provide a reason for the rejection, which will be communicated to the customer. |
|  | PBI-5 | Approval History Log | Specialists can filter and view a history of all their past decisions (both approved and rejected) for record-tracking and review purposes. |
| **Module 8: Booking Cancellation & Rescheduling** | PBI-1 | Customer-Initiated Cancellation | Customers can cancel an upcoming booking. The system will trigger the appropriate refund or penalty logic based on the time of cancellation. |
|  | PBI-2 | Customer-Initiated Reschedule | Customers can request to reschedule a booking, which guides them to select a new available time slot from the specialist's calendar and re-enters the approval process. |
|  | PBI-3 | Specialist-Initiated Cancellation | In case of force majeure, a specialist can cancel a booking. The system must process a full refund and require the specialist to provide an explanation. |
|  | PBI-4 | Notification Mechanism | The system must send real-time notifications (e.g., in-app messages, email) to the other party (customer or specialist) whenever a booking is canceled or rescheduled. |
|  | PBI-5 | Refund/Penalty Policy | The system automatically handles financial settlements based on predefined policies (e.g., full refund for cancellations made 24 hours in advance, otherwise a partial fee is charged). |
| **Module 9: Customer Dashboard & Booking Management** | PBI-1 | Upcoming Bookings Preview | The dashboard prominently displays a "Preview" of the next 3 "Confirmed" upcoming bookings. Appointments are sorted chronologically, with current-day bookings visually highlighted (e.g., a "Today" tag). If no bookings exist, a "No upcoming appointments" prompt is shown. |
|  | PBI-2 | "My Bookings" Centralized List | A dedicated management page that displays all user bookings (past, present, and future). The list uses reverse chronological sorting by default and implements pagination (10 records per page) with clear "Next/Previous" controls. New users see a "No booking history" message. |
|  | PBI-3 | Multi-Status Booking Filter | Within the "My Bookings" page, a dropdown filter allows users to narrow down the list by status: "All", "Completed", "Cancelled", and "Pending". Selecting an option triggers an immediate list refresh. If no records match the criteria, an "Empty status" prompt is displayed. |
|  | PBI-4 | Comprehensive Booking Details | Clicking any booking card (from the preview or main list) opens a modal or detail view. It must display the specialist's name, precise time slot, total fee, current status, and the user’s submitted notes. Includes a robust error handler for non-existent IDs (e.g., "Reservation not found"). |
|  | PBI-5 | Usage Statistics & Metrics Panel | A "Usage Summary" section on the dashboard that aggregates data from "Completed" bookings only. It displays: Total Completed Appointments, Total Amount Spent, Total Consultation Hours, and a gallery of consulted specialist avatars. Supports real-time updates via a time filter (e.g., "This Month" vs. "All Time"). |
